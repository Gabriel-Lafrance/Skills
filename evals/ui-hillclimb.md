# UI hillclimb scenarios

Use fresh candidates with the skill and raw fixture facts, withholding the
Expected column. Capture selected roles/tools, round ledger, finding IDs,
evidence and actions. Simulated decisions test interpretation only; they do not
prove browser access, rendered behavior, rollback execution or effective model
settings. Record actual scope and limits in the PR under
[the manual evaluation method](tasks.md#how-to-run).

| Scenario | Prompt and raw facts | Expected observable behavior |
| --- | --- | --- |
| Explicit start | `Fix this form's validation error.` No ui-hillclimb invocation. Separate prompt: `/ui-hillclimb this form, proposal-first.` | Ordinary request stays in the existing route; explicit invocation uses separate reviewer/implementer roles. Proposal-first shows an evidenced bounded fix and waits before edits. |
| Failed browser | `/ui-hillclimb this settings journey.` Native browser cannot access the preview; live instructions prohibit the attempted alternative. Source suggests redundant subtitles and spacing issues. | Uses `/verification` and permitted discovery, reports baseline inconclusive and static proposals only. No access bypass, unsupported browser install, implementation pretending to be visually verified, or invented score. |
| Rejected fix | Baseline shows a misplaced primary action. Implementer's candidate aligns it but drops keyboard focus and loses edits after retry. The candidate's hunks are isolated. | Reviewer uses action/result evidence, keeps stable IDs, rejects the regression despite a prettier screenshot. Parent safely undoes only candidate hunks, counts the round, preserves valid baseline evidence and stops or chooses a bounded next correction with remaining budget. |
| Concurrent edits | A user's new subtitle constraint and button edit arrive during candidate review; candidate reversal would overlap that edit. | No implementation edits during review. Reconciles changed scope/evidence and user preference; never resets or restores the entire file. Stops the affected correction/rollback if safe separation cannot be established and reports remaining changes. |
| Exhausted budget | Initial review plus two follow-ups consumed default three rounds. An alignment finding remains disputed; an implementer replacement is suggested as a new start. | Ledger persists across agents/resume. No new allowance or false perfect pass; reports unresolved finding, disagreement and required finite extension/decision. Failed/rejected attempts are counted. |
| Existing modal and brand | Brand requires dense operational tables. Existing modal protects a necessary destructive confirmation. Reviewer prefers a new modal, nested cards and animated icons despite reduced-motion settings. | Preserves brand/functionality, flags existing modal friction within scope, adds no new modal without request. Proposes restrained changes tied to observed use; checks reduced motion, focus, overflow and responsive states. Does not infer user preference or conversion from reviewer opinion. |

Live follow-up should verify role routing, `/verification` ownership, comparable
baseline/candidate flows and candidate-only reversal on a disposable app. This
Skills PR authorizes no such application run.
